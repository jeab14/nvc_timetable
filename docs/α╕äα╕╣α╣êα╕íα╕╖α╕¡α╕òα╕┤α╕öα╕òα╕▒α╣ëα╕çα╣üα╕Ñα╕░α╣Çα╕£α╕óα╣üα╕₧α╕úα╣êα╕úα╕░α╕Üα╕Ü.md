# คู่มือติดตั้งและเผยแพร่ระบบ NVC Smart Timetable

## 1. ส่วนประกอบของระบบ

| ส่วน | เทคโนโลยี |
|---|---|
| ภาษา | Python 3.12 ขึ้นไป (ทดสอบแล้วกับ Python 3.13) |
| หน้าเว็บ | Streamlit (`streamlit_app.py`) |
| ฐานข้อมูลใช้งานจริง | PostgreSQL (ทดสอบแล้วกับ PostgreSQL 16) ผ่าน SQLAlchemy + psycopg2 |
| ฐานข้อมูลพัฒนา/ทดสอบ | SQLite (สร้างไฟล์ `local_dev.sqlite3` อัตโนมัติเมื่อไม่ได้ตั้งค่า DATABASE_URL) |
| ตัวจัดตาราง | Google OR-Tools CP-SAT |
| ส่งออก | fpdf2 + uharfbuzz (PDF ภาษาไทย), openpyxl (Excel), CSV UTF-8 |
| ฟอนต์ | Sarabun (SIL Open Font License, รวมไว้ใน `assets/fonts/` พร้อมไฟล์สัญญาอนุญาต `OFL.txt`) |

> **สำคัญ:** Streamlit Cloud ไม่มีพื้นที่จัดเก็บถาวร ไฟล์ที่เขียนลงเครื่องจะหายเมื่อแอปรีสตาร์ต
> ระบบใช้งานจริงต้องตั้งค่า `DATABASE_URL` ชี้ไปยัง PostgreSQL ภายนอกเสมอ — ถ้ายังใช้ SQLite หน้า **ตั้งค่า > สถานะระบบ** จะแสดงคำเตือน

## 2. ติดตั้งและทดลองบนเครื่องคอมพิวเตอร์ (VS Code / Terminal)

```bash
# 1) แตกไฟล์โครงการ แล้วเข้าไปในโฟลเดอร์
cd nvc_timetable

# 2) สร้าง virtual environment (แนะนำ)
python -m venv .venv
# Windows:  .venv\Scripts\activate      macOS/Linux:  source .venv/bin/activate

# 3) ติดตั้งไลบรารี
pip install -r requirements.txt

# 4) เริ่มระบบ (ใช้ SQLite ในเครื่องอัตโนมัติ)
streamlit run streamlit_app.py
```

เปิด http://localhost:8501 → ครั้งแรกระบบจะแสดงหน้า **ตั้งค่าระบบครั้งแรก** ให้สร้างบัญชีผู้ดูแลระบบ

ทดลองด้วยข้อมูลสมมติ: เมนู **นำเข้าข้อมูล** > ดาวน์โหลด “ชุดไฟล์ตัวอย่าง” หรือเลือกไฟล์ทั้งหมดในโฟลเดอร์ `sample_data/`
(สร้างชุดตัวอย่างใหม่ได้ด้วย `python scripts/make_sample_data.py` — เป็นข้อมูลสมมติทั้งหมด ไม่ใช่ข้อมูลบุคคลจริง)

## 3. เตรียมฐานข้อมูล PostgreSQL

เลือกได้ทั้งบริการคลาวด์ (เช่น Neon, Supabase, Aiven — มีแผนเริ่มต้นแบบไม่มีค่าใช้จ่าย) หรือเซิร์ฟเวอร์ของวิทยาลัยที่เข้าถึงได้จากอินเทอร์เน็ต

1. สร้างฐานข้อมูลใหม่ เช่น `nvc_timetable` และผู้ใช้ที่มีสิทธิ์สร้างตารางในฐานข้อมูลนั้น
2. คัดลอก connection string ในรูปแบบ
   `postgresql://USER:PASSWORD@HOST:5432/nvc_timetable?sslmode=require`
   (ระบบแปลงเป็น `postgresql+psycopg2://` ให้อัตโนมัติ)
3. ไม่ต้องสร้างตารางเอง — ระบบสร้างตารางทั้งหมดเมื่อเริ่มทำงานครั้งแรก
   (ถ้าต้องการตรวจ/สร้างเอง ดูไฟล์ `docs/schema_postgresql.sql` ซึ่งสร้างจาก `python scripts/export_schema.py`)

ทดสอบการเชื่อมต่อจากเครื่อง:

```bash
# macOS/Linux
export DATABASE_URL="postgresql://USER:PASSWORD@HOST:5432/nvc_timetable?sslmode=require"
# Windows PowerShell
$env:DATABASE_URL="postgresql://USER:PASSWORD@HOST:5432/nvc_timetable?sslmode=require"
streamlit run streamlit_app.py
```

หรือสร้างไฟล์ `.streamlit/secrets.toml` (คัดลอกจาก `.streamlit/secrets.toml.example`) — ไฟล์นี้อยู่ใน `.gitignore` แล้ว **ห้าม commit**

## 4. เผยแพร่บน Streamlit Community Cloud

1. อัปโหลดโครงการขึ้น GitHub (ตรวจว่าไม่มี `.streamlit/secrets.toml` และ `local_dev.sqlite3` ติดขึ้นไป)
2. เข้า https://share.streamlit.io → **Create app** → เลือก repository / branch
3. **Main file path:** `streamlit_app.py`
4. **Advanced settings**
   - Python version: 3.12 หรือ 3.13
   - Secrets: วาง
     ```toml
     DATABASE_URL = "postgresql://USER:PASSWORD@HOST:5432/nvc_timetable?sslmode=require"
     ```
5. กด **Deploy** — Streamlit Cloud ติดตั้งไลบรารีจาก `requirements.txt` (ไม่ต้องมี packages.txt เพราะทุกไลบรารีมี wheel สำเร็จรูป)
6. เปิดแอป → สร้างผู้ดูแลระบบคนแรก → **ตั้งค่า**: เพิ่มภาคเรียน, ตั้งรหัสผ่านเริ่มต้น, ยืนยันกติกาแปลงชั่วโมงเป็นคาบ → นำเข้าข้อมูล

**หลังรีสตาร์ตแอป** ข้อมูลทั้งหมดยังอยู่ เพราะเก็บใน PostgreSQL ผู้ใช้เพียงเข้าสู่ระบบใหม่

**เมื่อฐานข้อมูลไม่พร้อมใช้งาน** หน้าเว็บจะแสดง “ไม่สามารถเชื่อมต่อฐานข้อมูลได้” พร้อมคำแนะนำ และไม่ทำงานต่อจนกว่าจะเชื่อมต่อได้ (ไม่มีการสร้างข้อมูลแทน)

**ข้อควรทราบเรื่องทรัพยากร:** Streamlit Community Cloud มีหน่วยความจำ/CPU จำกัด การจัดตารางใช้เวลาตาม “เวลาประมวลผลสูงสุด” ที่ตั้งไว้ (ค่าเริ่มต้น 60 วินาที) สำหรับวิทยาลัยขนาดใหญ่ แนะนำจัดทีละแผนกโดยใช้ฉบับฐาน หรือรันบนเซิร์ฟเวอร์ที่มีทรัพยากรมากกว่า (คำสั่งเดียวกัน `streamlit run streamlit_app.py`)

## 5. โลโก้วิทยาลัย

วางไฟล์โลโก้ที่ได้รับอนุญาตชื่อ `assets/logo.png` ระบบจะแสดงที่หน้าเข้าสู่ระบบอัตโนมัติ (ถ้าไม่มีไฟล์ จะแสดงไอคอนแทน)

## 6. การสำรองและกู้คืนข้อมูล

ระบบเก็บข้อมูลทั้งหมด (ข้อมูลหลัก ข้อมูลต้นทางที่นำเข้า ตารางทุกฉบับ ประวัติการแก้ไข บัญชีผู้ใช้) ใน PostgreSQL

```bash
# สำรอง (แนะนำทำทุกวัน/ก่อนเผยแพร่ตารางใหม่)
pg_dump "postgresql://USER:PASSWORD@HOST:5432/nvc_timetable?sslmode=require" -Fc -f nvc_backup_$(date +%Y%m%d).dump

# กู้คืนลงฐานข้อมูลใหม่ที่ว่างเปล่า
pg_restore -d "postgresql://USER:PASSWORD@HOST:5432/nvc_timetable_restore?sslmode=require" --no-owner nvc_backup_YYYYMMDD.dump
```

บริการคลาวด์ส่วนใหญ่มีระบบสำรองอัตโนมัติ/Point-in-time restore ให้เปิดใช้งานด้วย
นอกจากนี้ส่งออก Excel/CSV ของตารางที่เผยแพร่เก็บไว้เป็นเอกสารได้จากหน้า **ดูตาราง**

## 7. การรันชุดทดสอบ

```bash
pip install -r requirements-dev.txt
python -m pytest -q                       # ทดสอบด้วย SQLite ชั่วคราว
# ทดสอบกับ PostgreSQL จริง (ฐานข้อมูลทดสอบที่ลบข้อมูลได้เท่านั้น — ชุดทดสอบจะลบตารางทั้งหมด)
NVC_TEST_DATABASE_URL="postgresql+psycopg2://USER:PASS@HOST:5432/nvc_test" python -m pytest -q
```

```
│   ├── config.py               การตั้งค่า/อ่าน DATABASE_URL

│   ├── readiness.py            ตรวจสอบความพร้อมก่อนจัด
│   ├── problem.py              แปลงข้อมูลเป็นรายการสอนที่ต้องจัด
│   ├── solver.py               ตัวจัดตาราง CP-SAT
│   ├── validator.py            ระบบตรวจสอบตารางอิสระ
│   ├── timetable_service.py    ฉบับตาราง แก้ไขด้วยตนเอง ย้อนกลับ อนุมัติ เผยแพร่ คำขอ
│   ├── views.py / render.py    มุมมองตารางตามสิทธิ์ และการจัดรูปแบบตาราง
│   ├── export/exporters.py     PDF / Excel / CSV
│   └── ui/                     หน้าเว็บแต่ละหน้า
├── assets/fonts/               ฟอนต์ Sarabun + OFL.txt
├── sample_data/                ข้อมูลตัวอย่างสมมติ (หัวคอลัมน์หลากหลาย)
├── scripts/                    สร้างข้อมูลตัวอย่าง / ส่งออก DDL
├── tests/                      ชุดทดสอบ pytest
└── docs/                       คู่มือ รายงานผลทดสอบ ข้อจำกัด โครงสร้างฐานข้อมูล
```
